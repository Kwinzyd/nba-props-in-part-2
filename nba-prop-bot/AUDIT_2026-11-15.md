# NBA Props Bot audit — November 15, 2026

The bot has not demonstrated a reliable betting edge in the current-season
alert history. Repairing observability and risk controls is justified now;
increasing stakes or promoting newly trained models is not supported by these results.

## Evidence and scope

Reviewed the local source, scheduler, settlement, alerting, calibration and risk
paths, November 14 production logs, and the active PostgreSQL database through
read-only connections. The SQLite databases are historical copies: the main
local copy stops on May 6 and is not the current production record.

Current-season figures below cover alerts from October 22 through November 14,
2026, excluding pushes/voids. They describe recorded alert recommendations,

## Fixes implemented

1. **Daily drift monitor was broken on PostgreSQL.** November 14 logs contain
   `syntax error at or near "OR"`; `model_health` contained zero snapshots.
   Replaced SQLite-only `INSERT OR REPLACE` with an upsert supported by both
   backends and quoted the PostgreSQL reserved identifier `window`. The monitor
   now scores the calibrated probability actually stored with the alert, uses
   only previous dates in the historical baseline, and no longer claims a
   retrain happened merely because an alarm fired. It still needs seven daily
   baseline snapshots before its existing alarm logic becomes available.
2. **Breaking-news delivery dropped messages.** The logs repeatedly show
   Telegram HTTP 400 errors for unsupported `<p>` tags. Strip RSS markup and
   escape external fields before placing them inside the Telegram HTML template.
3. **Calibration reporting used future information and an invalid join.**
   Matching CLV rows by player and market could duplicate alerts across dates,
   books and sides, and adding closing probability to edge did not reproduce
   the original prediction. Score one row per alert using stored `model_prob`,
   with the historical edge-plus-alert-implied fallback. Exclude pushes and
   invalid probabilities.
4. **Rounding could exceed stake limits.** A capped stake below $5 became $5;
   other roundings could also increase exposure beyond its calculated amount.
   Bound the rounded prop, game and parlay suggestions by their calculated,
   capped stake.
5. **PostgreSQL risk-limit checks were vulnerable to concurrent inserts.**
   An `INSERT ... SELECT` alone does not serialize competing transactions.
   Risk-limited prop inserts now acquire the same transaction advisory lock
   before reading exposure. This applies to `insert_alert_with_limits`; callers
   that use unrestricted `insert_alert` still require their own review.
6. **Settlement queries broke the documented SQLite backend.** Replaced
   PostgreSQL-specific casts and placeholders with portable date expressions
   and placeholders already supported by the PostgreSQL adapter.
7. **Some existing tests depended on local artifacts or incomplete fixtures.**
   BDL bridge tests now run its constructor; calibration fallback tests isolate
   themselves from trained files on disk.

## Open findings and next changes

- **Model promotion:** the calibrated alert probabilities remain overconfident
  and the broader candidate sample does not beat the price baseline. Keep model
  changes behind chronological evaluation by game/date and a market-baseline
  promotion check. Existing XGBoost auto-retraining is disabled by default;
  training still needs review for feature availability at historical timestamps
  and time-ordered validation. No fitted artifacts or strategy thresholds were
  changed during this audit.
- **Settlement backlog:** current-season unresolved dates include October 31
  (two alerts), November 8 (one), and November 10 (one). Older May/June records
  also remain open. The four-day retry window abandons older failures. Add an
  explicit backlog report and event-aware recovery rather than assuming absent
  player stats mean a push. Historical quarter/half/team markets need distinct
  settlement logic before re-enabling them.
- **Closing-line coverage:** only 187 observations have no-vig CLV in the
  current-season sample. Positive vigged CLV (+1.14 points across 314 rows)
  masks negative no-vig CLV. Track missing closes by reason, market and book.
- **Duplicate recommendations:** 22 current-season player/market/side/date
  groups contain multiple alerts. Different lines can be intentional, but
  player exposure needs a stronger identity rule and an atomic deduplication
  check across concurrent scans.
- **Risk accounting:** the configured daily limit is actually a rolling
  12-hour total. Event risk also expires after 12 hours; unrestricted game-market
  inserts bypass the new serialization. Define the intended day/open-exposure
  semantics before expanding execution.
- **Drift thresholds:** the existing sigma comparison mixes rolling-window
  scores with variation of cumulative historical averages. Restoring snapshots
  fixes execution, but does not validate that statistical alarm design.
- **Operational integrations:** logs show Sportradar 403s, an unavailable
  OpenRouter fallback model, repeated unreachable Nitter feeds with RSS fallback,
  Redis running in no-op mode, and a 350-second watchdog stall. These need
  separate capability/latency checks; do not treat fallback logs as proof those
  data sources are healthy.
- **Existing live-model tests:** correlated-position dampening rounds a $5
  position back to $5, and the possession-enriched model can return a lower
  probability than the basic approximation despite favorable micro-state.
  Resolve the intended sizing precision and compare enriched states within the
  same probability model before changing numerical assumptions to satisfy tests.

## Validation and rollout

Regression tests cover news HTML, snapshot idempotence and baseline exclusion,
stored-probability scoring, calibration push exclusion, SQLite settlement and
repeat settlement, and stake caps. PostgreSQL reads and snapshot upsert syntax
were checked against the active database using read-only queries and `EXPLAIN`
without executing writes. The transaction lock has not been load-tested against
concurrent production writers.

Final test run: **205 passed, 2 failed**. Both failures existed before these
changes and are the live-model issues described above. The targeted regression,
calibration and BDL test run passed all 51 tests.

The running scheduler has not been restarted. Source changes take effect on a
subsequent restart. Production records, queued messages, credentials, fitted
models and strategy flags were not intentionally changed. Existing modified
XGBoost pickle files predated this work and were left untouched.
